新しい意思決定モデルをベースにした公開プロジェクトはおよそ300件ある。そのうち「スコアリングとランキング」を扱うもの（26件）を全部見てみたんだけど、どれもこれもモデルに意見を聞くだけでスコアをつけていた。この論文を8つの品質軸で評価して、このコピーのセンスを評価して、この文書が関連しているか判定して、といった具合だ。

それってデータと言えるだろうか？単にモデルの意見に数値を貼り付けただけで、このカテゴリ全体が正直その上に成り立っている。

そこで、実際に誰かが測定した結果を使ってモデルをトレーニングした。いじってみたい人向けにウェイトも公開している。**[`NovusEdge/vera-deberta-v3-large`](https://huggingface.co/NovusEdge/vera-deberta-v3-large)**、Apache 2.0、435Mパラメータ、1回のフォワードパスで短い説得力のあるテキストをスコアリングする。ベースは[`com-kotobalabs/open-jev-deberta-v3-large`](https://huggingface.co/com-kotobalabs/open-jev-deberta-v3-large)で、型付き決定（typed decisions）で事前学習されたDeBERTa-v3-largeそのものだ。

| 指標 | 本モデル | ランダム | Gemini 3.1 Pro |
|---|---|---|---|
| ペアワイズ正解率（未見のスプリット） | **0.812** | 0.546 | 0.751 |
| クリーンなペアのみ | **0.797** | 0.546 | - |
| 4〜5個のバリアントから最良を選択 | **47.7%** | 23.0% | - |
| 最悪のバリアントを回避 | **90.3%** | 77.0% | - |
| Redditのタイトルペア（ドメイン外） | 0.522 | 0.500 | - |

32,487件のランダム化された見出し実験から得られた62,695件の実際のA/Bアームで学習されており、上記の数値はすべてモデルが一度も見たことのないスプリットからのものだ。ここに至るまでの経緯は以下の通りで、最初のベンチマークが文字通り何も測定していなかった話も含まれている（うん、まだ少し根に持っている）。

## セットアップ

これにぴったりのデータセットが存在していて、2021年から公開されていた。2013年1月から2015年4月にかけて、Upworthy（そう、あの「この後起こったことに誰もが驚いた」のUpworthy）が自社の見出しで32,487件のランダム化A/Bテストを実施した。実際のトラフィック、実際のランダム化、5億3,800万回の割り当て。そしてコーネル大学がそのすべてを[Upworthy Research Archive](https://osf.io/jd64p/)としてCC BYで公開した。すべての見出しバリアント、インプレッション、クリックが含まれている。

これは短い説得テキストにおけるグラウンドトゥルース（正解データ）として、これ以上ないほど近いものだ。

構成としては、回帰ヘッドを付けたModernBERT-largeで、ターゲットは各テスト自体の平均を中心化した縮小ロジットクリック率だ。ちなみに中心化は重要で、クリック率のばらつきの大半は*記事そのもの*に起因しており、見出しだけでは説明がつかない。だから実際に予測したいのは、あるアームが実施されたテストの平均からどれだけ離れているかなのだ。そしてその平均に向けたベータ二項縮小を行うことで、600インプレッションのアームは主に事前確率として、20,000インプレッションのアームは主に明確な証拠としてカウントされる。

単一のL4で25分、費用は約40セント。2015年1月以降のデータをすべてホールドアウトしてテストしたところ、**ペアワイズ正解率0.704**を達成した。

規模感を把握するために言うと、フィルタなしのペアに対して公開されている最も近い数値は、手作りの言語的特徴量を使ったトロントのグループによる[0.544](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0281682)で、彼らの論文ではこの問題は「単なるサンプルサイズの問題ではなく、本質的に難しい」と結論づけている。この0.544が見た目以上に悪い比較対象である理由については後で触れるし、後ほど他人の数値を引用するのをやめて自分で比較を実行することになる。

それより16ポイント高い精度が、40セントで手に入った。だから当然、私はこう書き記した。「見出しのシグナルは2年間のドリフトに耐える」。

## しかし

そのタイトルで主張していたのは、シグナルが*ドリフト*に耐えるということだった。学習データは2013〜2014年、テストセットは2015年で、精度はほとんど変わらなかったからだ。2年間にわたるネット文化の変化など、モデルは気にも留めていないようだった。もし本当なら素晴らしい発見だし、この取り組みの本来の目的は最終的にメールの件名に適用することなので重要だ。もし単一のパブリッシャー内で2年の変化に耐えられないなら、完全に異なるメディアへの移行に耐えられるはずがない。

アーカイブは3つのスプリット（exploratory、confirmatory、holdout）で提供されており、私はconfirmatoryで学習とテストを行っていた。そのため、主に念のため、そしてすでに「分かっている」ことを追認するつもりで、残りの2つに対して同じウェイトでスコアを計算してみた。

```
confirmatory 2015:  0.704
holdout:            0.637
exploratory:        0.624
```

最高だな。

一度も触れていなかった2つのスプリットが、*すべての効果量ティア*において0.013以内で一致し、どちらも私の見出しの数値が7ポイント水増しされていたことを告げていた。

![Upworthyアーカイブの3つのスプリットにおけるペアワイズ正解率。confirmatoryの2015年の線は、互いに密接に追従するholdoutとexploratoryを大きく上回っている。](/assets/img/blog/decision-models/splits.png)

## 横にしか移動しないタイムマシン

そこで今回はアーカイブのドキュメントをちゃんと読み直してみたところ、アーカイブはテストをスプリットへ**ランダムに**割り当てていることが判明した。時系列順ではなく、ランダムだったのだ。

![2つのバー。1つ目は学習の後にテストが来るきれいな時系列スプリット。2つ目は実際の構造で、期間全体にわたって学習ブロックとテストブロックが交互に配置されている。](/assets/img/blog/decision-models/split-structure.png)

| スプリット | アーム数 | 日付範囲 | 2015年以前の割合 |
|---|---|---|---|
| confirmatory | 51,891 | 2013-01-24 → 2015-04-30 | 83.5% |
| holdout | 11,231 | 2013-01-24 → 2015-04-29 | 82.8% |
| exploratory | 10,804 | 2013-01-26 → 2015-04-29 | 83.8% |

3つのスプリットはすべて同じ期間を同じ割合でカバーしている。つまりholdoutでスコアを計算したとき、テスト対象の83%は*学習期間内*のものだった。同じ時代、同じ文体、すべてが同じで、単にモデルが見たことのないテストだっただけなのに、2015年の末尾データよりも*悪い*スコアを出したのだ。

見方を変えると少し笑えてくる。時間の経過による損失はほぼゼロなのに、同じ期間の未見テストでは7ポイントも落としている。私が綿密に構築したはずのドリフトテストは、最初からテストの個別性を測っていただけで、時間的汎化の皮を被っていたに過ぎなかった。

横にしか進めないタイムマシンを作ってしまっていたわけだ。

## 2つの仮説、どちらも逆だった

次に思い浮かぶのは当然リーク（情報漏洩）だ。Upworthyは同じ記事を何十もの見出しバリアントで書き直していたため、*テスト*をランダムに分割すると、1つの記事のリライトが3つのスプリットすべてに散らばり、holdoutは学習テキストのほぼコピーで溢れかえるはずだ。

各評価見出しと、モデルが実際にフィットした38,950件の見出しとの間の最大Jaccardトークン重複率を測定する簡単な転置インデックスを作ってみた（完全一致文字列検索では650件中5件の共有見出しが見つかっており、それをもってリークは「排除された」と判断していた）。

| 評価セット | n | 重複率≥0.9 | 中央値 |
|---|---|---|---|
| confirmatory 2015 | 1,300 | 0.5% | 0.227 |
| holdout | 4,274 | **30.5%** | 0.300 |

30%だ。2015年の末尾データと比べて60倍も汚染されているのに、スコアは**低かった**。

したがってリークはこのギャップを説明できないし、向きが完全に逆だ。むしろ、ほぼコピーされたテキストを取り除けば、真っ当なholdoutの数値は0.637よりも*悪化*するはずだ。それも確認するため、ペアごとのスコアを出力してスライスしてみたところ、純粋にクリーンなペアでモデルは0.646を出し、わずかに*改善*した。つまり、ほぼ重複したデータは何の役にも立っていなかった。

では、ラベルノイズだろうか？もしかするとholdoutペアのインプレッション数が少ないだけかもしれない。

| 評価セット | インプレッション中央値 | zスコア中央値 | CTR比中央値 |
|---|---|---|---|
| confirmatory 2015 | 2,462 | 2.37 | 2.24 |
| holdout | 3,096 | 2.64 | 1.99 |

これも逆だった（笑）。holdoutペアの方がインプレッション数が*多く*、zスコアも*高い*。2015年のセットはCTR比の中央値が広く（1.99に対して2.24）、ペアの識別が純粋に容易であることは確かだが、7ポイントもの差を説明できるほどではない。

そこでドキュメントに「原因不明」と書いて先へ進むことにした。数値は0.63であり、2つの独立したスプリットがそれで一致している。一致しない1つが外れ値なのだが、その理由は説明がつかない。

**!! オタクの知識垂れ流しアラート :3 !!**

## 実際に重要だった部分

自分の目玉だった結果を打ち砕いた後、少なくともアブレーション（除去実験）くらいはきちんとやろうと考えた。

データ量を増やせば勝てるだろうと予想していた。それが退屈な事前知識というものだし、62,695アームもあるのだから、3つ目のスプリットを投入して増やせばいい。そこで、学習にexploratoryスプリットを追加する実験と、損失関数を変更する実験の2つを用意し、どちらも同じ2,137組のholdoutペアで評価した。

```
Phase 0        confirmatory       MSE              0.637
more-data      expl+confirmatory  MSE              0.724
rank           confirmatory       Bradley-Terry    0.775
rank+more      expl+confirmatory  Bradley-Terry    0.787
```

![アブレーション結果。データの追加でベースラインから0.087向上。Bradley-Terryへの切り替えで0.138向上し、最良の実行では0.812に達する。](/assets/img/blog/decision-models/ablations.png)

学習データを28%増やして得られたのは**+0.053**だったが、損失関数の変更は3エポックではなく2エポック、しかも少ない学習セットで**+0.107**を叩き出し、2倍の差をつけて圧勝した。

振り返ってみれば当たり前のことだったが、最悪なタイプの「当たり前」だった。ベンチマークは*ペアワイズ正解率*（2つの見出しが与えられたときに勝者を当てる）なのに、私はクリック率への回帰を行っていた。指標のプロキシ（代理）を最適化しておいて、その指標自体で自分を採点していたのだ。

[Bradley-Terry](https://en.wikipedia.org/wiki/Bradley%E2%80%93Terry_model)は実際の目的そのものを最適化する。1つのテスト内のすべてのペアについて、少ない方のアームの対数インプレッション数で重み付けした `logsigmoid(score_winner - score_loser)` を最大化する。私の38,950件の学習アームは、テスト内ペア63,597組へと変換された。

同じモデル、同じデータ、異なる目的関数。それだけで14ポイントの差が出た。

好奇心からModernBERT-*base*（パラメータ数は3分の1）も実行してみたところ0.761を記録した。つまり、効果の大半はモデルのサイズではなく目的関数とデータに起因している。CPUで動かしたい場合には嬉しい結果だ。

そして、見逃しかけた出来事があった。意思決定タスクで事前学習されたDeBERTa-v3-largeのバリアントを試したところ、4,804ステップの間ずっとぴったり `-log(0.5)` に張り付き、スコアはランダム相当の0.519で完全に横ばいだった。

これを「DeBERTaは劣っている」と解釈して流してしまうのは簡単だし、実際そうしかけた。だが「当てずっぽう」を意味する正確な値で*完全に*平坦な損失曲線というのは極めて特異な兆候であり、学習がうまく進んでいないモデルの挙動とは異なる。エンコーダのロードも正常で、新しく初期化されたのは分類器とプーラーだけだった。

原因は学習率だった。DeBERTa-v3-largeはModernBERTが好む2e-5では[極めて不安定](https://github.com/microsoft/DeBERTa/issues/77)になることで知られており、6e-6あたりを求めていた。それなのに同じ設定を使い回していたのだ。

6e-6で再実行したところ、損失は 0.709 → 0.682 → 0.620 → 0.360 と推移し、最終的に**0.812**を叩き出した。ModernBERTを2.5ポイント上回り、最高信頼度ティアでは0.913に達した。

この時点では自分を信用できなくなっていたので、ほぼ重複したデータのスライスでもテストしてみた。学習データに類似するものが一切ない真にクリーンなペアにおいて、ModernBERTの0.769に対して**0.797**を記録した。また、スコアを伸ばしながらも暗記によるギャップはModernBERTより*小さく*なっており、これは丸暗記で勝っているモデルの挙動とは正反対のものだ。

つまりシステムはずっと正常に機能していた。単に数値を1つ間違えていただけだった。

## しかし、0.812は実際*何を意味する*のか

正直なところ、人間にとっては何も意味しない。それがペアワイズ正解率を主張として使う際の問題点だ。順序が合っていることしか分からず、その大きさについては何も教えてくれない。2つの見出しを81.2%の確率で正しく順序付けできることは、両者の実際の差に応じて、途方もない価値を持つこともあれば無価値なこともある。

そこで、実際に配信する人間がどう感じるかを測定してみた。各テストについて、モデルが最高スコアをつけたアームを取り出し、その実際のクリック率をそのテスト内の全アームの平均と比較した。モデルがなければ特定のバリアントを優先する理由がないため、送信したかもしれないものの平均が真っ当な反事実（counterfactual）になるからだ。

| | CTR |
|---|---|
| テスト平均（モデルなし） | 1.20% |
| モデルの選択 | 1.42% |
| オラクル（完璧な選択） | 1.60% |

2,140件のテスト全体で**相対クリック率+18.3%**となる。ただ、この数値面での期待はすぐに取り下げなければならない。

### リフト値の数値は別の環境には通用しない

18.3%というのはUpworthy特有の事実だ。彼らの1.20%というベースレートや、ライターがバリアント間にどれだけ差をつけていたかに依存している。そのため、クリック率2.5%でバリアントの差がより狭いB2Bニュースレターにこれを当てはめた場合、数値は変化するし、どちらに転ぶか予測がつかない。

*通用する*のは、単一テスト内の比率に関するものだ：

| 指標 | 値 |
|---|---|
| 最悪のバリアントを回避 | **90.3%** |
| テスト平均を上回る | 76.6% |
| 実際の最良バリアントを選択 | 47.7% |
| 獲得できたヘッドルーム（中央値） | 89.2% |
| スピアマン相関（スコア vs クリック率） | 0.526 |

**90.3%という数字こそ、私が自信を持って支持できるものだ。**自分が書いた最悪のものを配信してしまう事態をほぼ確実に防いでくれる。これは「+18.3%」とは異なり、ベースレートやオーディエンス、メディアが変わっても通用する。また、通常4〜5個のアームに対するTop-1正解率47.7%は、ランダムの約2.2倍に相当する。

ただ、この中には少し狡猾な数値もある。獲得ヘッドルームの中央値は89.2%（四分位範囲は5%〜100%）だが、全テストを通算すると55.4%になる。モデルはバイモーダル（二峰性）であり、大半のテストでは得られるはずのゲインをほぼすべて獲得する一方で、一部のテストではほとんど獲得できず、それらが全体の数値を引き下げているのだ。

その後、スコアに雰囲気ではなく単位を持たせるため、[等調回帰（アイソトニック回帰）](https://en.wikipedia.org/wiki/Isotonic_regression)を適用した。等調回帰がここで適しているのは単調性（スコアが高いほどクリック率が高い）のみを仮定しているからで、これはBradley-Terryが保証する内容そのものであり、文字通りそれしか保証しない。パラメトリックな手法を使うと、モデルが約束していない構造を捏造することになってしまう。区間推定はアーム単位ではなく*テスト単位*のブートストラップから得ている。1つのテスト内のアームは同じ記事を共有しており独立していないからだ。

| スコア | ベースライン比 | 90%信頼区間 |
|---|---|---|
| −2.72 | **−19.1%** | [−0.252, −0.209] pp |
| −1.06 | −8.2% | [−0.111, −0.086] pp |
| −0.20 | −0.7% | [−0.023, −0.000] pp |
| +0.56 | +3.7% | [+0.030, +0.056] pp |
| +1.62 | +11.1% | [+0.115, +0.147] pp |
| +2.82 | **+21.8%** | [+0.231, +0.274] pp |

![キャリブレーション曲線。ベースラインに対するクリック率はモデルスコアとともに単調に上昇し、90%区間がゼロをまたぐのは中央付近のみである。](/assets/img/blog/decision-models/calibration.png)

中央の行を見ると信頼区間がゼロをまたいでいる。これはモデルが「この2つは同じような見出しだから、コイントスのようなものだ」と正しく判断していることを示している。

## あの0.544について

後で触れると言っていた件だ。このアーカイブで他にどんな実験が行われていたかをきちんと調べたところ、頼りにしていた比較対象はかなり脆弱になり、見落としていた別の研究の重要性が浮き彫りになった。

| ソース | タスク | 指標 | 値 | ランダム |
|---|---|---|---|---|
| LOLA、人間 (n=4,571) | k個中のTop-1 | 正解率 | ~ランダム | 0.330 |
| LOLA、GPT-4 インコンテキスト | k個中のTop-1 | 正解率 | 0.400 | 0.330 |
| LOLA、LoRA Llama-3-8B | k個中のTop-1 | 正解率 | 0.469 | 0.330 |
| LOLA、ファインチューン済みGPT-4o | k個中のTop-1 | 正解率 | 0.488 | 0.330 |
| [arXiv:2506.00152](https://arxiv.org/abs/2506.00152)、Pythia-12B | 有意差ありペア + リード文 + タイムスタンプ | ROC AUC | 0.82 | 0.50 |
| [PLOS ONE 0281682](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0281682) | 記事+画像+週を一致させたペア、K≤15 | 正解率 | 0.544 | ~0.50 |
| **VERA** | テスト内の全ペア、見出しのみ | 正解率 | **0.812** | 0.546 |

これらの行はどれ一つとして私の実験と同条件の比較にはなっていない。それが重要な点だ。

0.544の論文は、記事、画像、*そして*テスト週を一致させたペアを作り、15ペアを超える実験はランダムにサブサンプリングしている。学習データは5,048ペアだ。さらにこれは事前登録研究であり、最初の仮説は「そもそもランダムより高い精度で予測できるか」という有意性検定だった。精度を最大化しようとしていた人は誰もいなかったのだ。1桁多いデータと435Mパラメータのモデルを使って27ポイント上回ったところで、誇れるような成果ではなかった。

実際に見落としていたのはPythia-12Bの報酬モデルで、このデータセットにおけるニューラルモデルの結果としては群を抜いて強力だ。ROC AUC 0.82。CTRの差が5%水準で有意なペア（おおよそ最も簡単な上位28%）のみで学習し、見出しと一緒に記事のリード文と投稿タイムスタンプも読み込んでいる。つまり、より簡単なラベルセットに対して、より多くの入力を与え、異なる指標で評価しているわけだが、0.812を上回ってはいない。しかし、2つの数値を並べてざっと眺めると同じように見えてしまうため、他人に指摘される前に自分で言及しておきたかった。

すべてを踏まえても残る事実がある。フィルタリングされていないテスト内ペアに対して、見出しテキストのみからファインチューニングされたエンコーダによるペアワイズ正解率を報告した者はいない。これは「SOTAを破った」というよりも狭い主張だが、私が責任を持って擁護できる主張だ。

## だから自分で比較してみた

上記の数値はすべて他人のデータであり、他人のペアで測定されたものだ。そこで、現行の2つのシステムを私のペアで走らせてみた。

各ペアを2回評価し、1回目は勝者を先頭に、2回目は2番目に配置して、両方の順序で同じ見出しを選んだ場合のみをカウントした。このプロトコルは重要だ。モデルは内容に関係なくスロットAをランダム以上の頻度で選ぶ傾向があるため、単一順序での実行ではモデル自身が都合よく選んだサブセットで採点してしまうことになる。

| システム | パラメータ数 | 一致ペア | 自己整合性 |
|---|---|---|---|
| **VERA** | 435M | **0.823** | — |
| Gemini 3.1 Pro | フロンティア | 0.751 | 83.7% |
| Laya typed-decisions | 421M | 0.504 | 52.9% |

これで、私が頼りにしていた論拠が崩れ去った。「人間はこのタスクでランダムと同等のスコアしか出せない」と言い、モデルにとってもこのタスクが難しいかのように仄めかしていた。だが実際は違った。Geminiは0.751を出す。人間の実験結果は人間に関するものであり、機械については何も語っていないのに、私は言えないはずのことを言うためにそれを利用していたのだ。

もっとも、実直な事実の方が魅力的だ。435Mのモデルが、1回の呼び出しあたり約1000分の1のコストで、フロンティアの推論モデルを7ポイント上回っている。それを知るために5.60ドル分のGemini呼び出しを使った。

Layaは誰もが気にするオープンな意思決定モデルだが、ここではコイントス並みの整合性しか出せなかった。そのままにしておくと酷い結果に見えるので補足すると、そのモデルカードの対象は請求書処理、セキュリティインシデント、カスタマーサービス、エージェントのトレースとなっている。見出しのクリック率はその4つのいずれにも該当しない。単にドメイン適合性の問題であり、VERAを請求書処理に持っていっても同じように無力だろう。

副産物がもう1つあった。Geminiは、クリック率の差が5%水準で有意でないペア（私がノイズと呼んでいたもの）で0.641を記録した。Geminiはこれらのラベルを見たことがない。つまり結果データにアクセスできないモデルであっても0.500を上回っているということは、それらのペアには実験の検出力不足で証明できなかった実際の差異が存在していることを意味する。同じ層でVERAが0.696を出したことにもリークの説明は不要であり、Geminiを実行するまで私はその2つの解釈を区別できずにいた。

## さて、ここから台無しにする

上記の数値はすべて、ある1社のパブリッシャーにおける2013〜2015年のバイラルなソーシャル見出しから得られたものだ。そして、私が本当に作りたいのはメールの件名をスコアリングするものなのだ。

購読登録した4,000人に送られるB2Bニュースレターは、「この少年は一言でワクチン反対論を完全に論破した」といった見出しとは共通点がほとんどない。

そこでテストしてみた。Redditは見方を変えればこのアーカイブと同じ構造を持っている。SNAPは、同じ画像が異なるタイトルでそれぞれ約8回再投稿された132,308件の投稿データを公開した。1つのアイテム、多数のテキストバリアント、測定された結果。16,242枚の画像。

ランダム化されていないため、まず3つの処理が必要だった。ペアは同一画像*かつ*同一サブレディット内で形成し、コミュニティ間の違いを相殺する。遅れて投稿されたものはそれだけで不利になるため、サブレディットごとの再投稿インデックスに対する減衰をフィットさせ、残差を順位付けした。そして、残差の差が勝者を特定できるほど十分に開いているペアのみを残した。

117,118ペア。VERAのスコアは**0.522**だった。ランダムは0.500。「タイトルの長い方が勝つ」というルールでは0.507になる。

そのサンプルサイズにおける標準誤差は0.0015なので、0.522はランダムより約15標準誤差高い。確かに有意ではあるが、実用には小さすぎる。精度は残差の差が広がるにつれて四分位数全体で 0.508 → 0.531 と上昇しており、このわずかな効果がアーティファクトではなくシグナルであることを示している。r/WTFでの0.495から、r/fffffffuuuuuuuuuuuuでの0.558まで幅があった。

つまり、0.812はUpworthy独自のものだ。VERAが学習した内容は、ある特定のパブリッシャーの2013年当時の文体であり、別のドメインには引き継がれない。

自分の補足にさらに補足をつけておく。Redditのアップボートはクリック率ではないし、投稿の時間帯や投稿者の評価はコントロールされていない。ここでのネガティブな結果から、「転移性がない」のか「交絡因子に埋もれた」のかを明確に切り分けることはできない。しかし、これは利用可能な最も安価で誠実なテストであり、結果は否定的だった。「転移性は未検証」と書いて読者に都合よく解釈させるよりは、テストを実行したかった。

本来やりたかったテストにはメールのデータが必要だ。そこで、送信後の結果が実際に測定されている公開メールデータを探したが、存在しなかった。

| ソース | 規模 | 入手性 |
|---|---|---|
| Return Path 件名調査 | 900万件の件名 | プロプライエタリ、2015年、未公開 |
| Belkins B2Bコーパス | 550万件のメール | 集計統計のみ |
| Yahoo (IEEE 7004277) | 10万件以上の件名、数十億のインプレッション | プロプライエタリ |
| OracleのNLORP論文 | 300件の件名 | Googleからスクレイピング、率は未測定 |
| 各種Kaggle「メールキャンペーン」セット | 多様 | モックまたは合成データ |

そのうちの1つはOracleの主任データサイエンティスト2名によるarXiv論文だが、そのデータセット全体は「Google検索を通じて複数のインターネットソースから収集された、特別セールのメールの300以上の異なる件名」となっている。彼らを揶揄しているわけではない。実際に世の中にあるのがそれだけなのだ。

集計結果自体はあちこちに転がっている（6〜10語が最も成果が良い、開封には21〜40文字、数字を含めると数ポイント上がる、など）。しかし、送信ごとの結果データは一切なく、モデルの学習に使えるものは何一つない。

## 取り組み全体の見方が変わる

セカンドオピニオンによって覆されるまで、私は都合のいいストーリーを自分に言い聞かせていた。そのストーリーとは、「*アーキテクチャはコモディティであり、持続的な資産はプロプライエタリな結果ラベルである*」というものだ。前半は正しいが、後半はナンセンスだ。なぜなら私はプロプライエタリなラベルなど*持っていない*からだ。Upworthyは公開されており、GPUを持つ人なら誰でも週末にコーヒー1杯以下の費用で私の0.812を再現できる。ウェイトをそのまま公開している理由もそこにある。4ドルしかかかっていないし、それを堀（モート）だと強弁することはできない。

私が実際に持っているのは実績だけだ。本当の資産とは、実際のトラフィックに対する継続的な測定ループのことであり、それはまだ存在しない。

私に必要なデータはメールサービスプロバイダ（ESP）の中に眠ったまま放置されている。A/Bテスト機能を備えたすべてのESPには、測定された結果を伴う何百万もの件名実験データがあるのに、それを使って何かを学習させているところはほぼ皆無だ。だから私に必要なのは新しいヘッドでも新しいベンチマークでもなく、そのログを持っている誰か一人なのだ。

## これが一般化できる対象

手順は正直なところ1行に収まるほど退屈だ。「測定された結果が存在するなら、それで学習させろ。モデルに意見を聞くのはやめろ」。

あなたの会社がこれまで実施したすべてのA/Bテストは、ラベルが付けられ、結果が紐付けられた状態で、何かの実験プラットフォームの中に放置されている。Optimizely、Statsig、LaunchDarklyなど、何を使っていようと、「この5つを試してこれが勝った」という何年分ものデータがあるのに、誰もそれを使って何も学習させていない。

候補セットがあり、ダウンストリームで数値が得られる場所ならどこでも、同じことが当てはまる：

| 意思決定 | 手元にすでにあるラベル |
|---|---|
| 件名、見出し、プッシュ通知のコピー | 開封数、クリック数 |
| サポートマクロの選択 | エスカレーションなしで解決 |
| 検索のリランキング | ユーザーが受け入れた検索結果 |
| エラーメッセージの文言 | 自己解決、またはチケット起票 |
| 商品リストのタイトル | コンバージョン |
| エージェントのツール選択 | トラジェクトリが成功したかどうか |

エージェントを開発しているなら、最後の行は面白いところだ。Jevの3つのプリミティブはchoice（選択）、score（スコアリング）、noul（無効）であり、この記事のすべては `score` に触れているが、決定の後に何が起こったかを誰かが記録している場所ならどこでも、同じ手法が `choice` にも機能する。そしてエージェントのルーティングに関して言えば、今のところ誰もそれを記録していない。

ただし、これらすべてに対する正直な限界もある。私にはデータポイントが1つしかない。結果に基づく学習は*1つのタスクにおいて*ゼロショットの判定を大きく上回ったが、その差が他の場所でも維持されるかどうかは未検証だ。だから数値ではなく、方向性に賭けるべきだ。

## VERA

**V**ariant **E**valuation from **R**eal **A**nalytics（実績アナリティクスによるバリアント評価）。

**[`NovusEdge/vera-deberta-v3-large`](https://huggingface.co/NovusEdge/vera-deberta-v3-large)**, Apache 2.0.

```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer

tok = AutoTokenizer.from_pretrained("NovusEdge/vera-deberta-v3-large")
model = AutoModelForSequenceClassification.from_pretrained(
    "NovusEdge/vera-deberta-v3-large")

# Score a set of candidates for ONE piece of content. Higher wins.
enc = tok(candidates, padding=True, truncation=True, max_length=64,
          return_tensors="pt")
scores = model(**enc).logits.squeeze(-1)
```

スコアは常にセットとして読み取り、決して単一の数値として見ないでほしい。学習ターゲットはテスト自体の平均からの乖離だったため、単一のスコア自体には何の意味もない。1回の配信のために作成した3〜6個のバリアントを与えると、それらをランク付けする。スコアを予想リフト値にマッピングするキャリブレーターも含まれている。

435Mが重すぎる場合は、CPUサイズのモデルも用意している。ModernBERT-baseはパラメータ数3分の1で0.761を達成する。

## できないこと

メールへの転移。あるいは少なくとも、転移するかどうかは私には全く分からない。

もしニュースレターを運営していて、開封率やクリック率を測定した過去の配信データをお持ちなら、ぜひ確かめてみたいので連絡してほしい。データはあなたのものだ。

## まとめ

この分野のオープンウェイトモデルの1つは、自身のtyped-decisionsベンチマークにおいてゼロショットで0.362を記録しており、これは最頻クラスベースラインの0.461を下回っている。

0.637から0.812への向上も、巧妙なモデリングによるものではない。その3分の2は指標に合致した損失関数を選択したことによるもので、残りは実際に何が起こったかを誰かが測定した62,695行のデータのおかげだ。だから、もしモデルに意見を聞くことでデータをラベリングしているなら、まずはグラウンドトゥルースを探しに行った方がいいかもしれない。おそらくすでにどこかに転がっているはずだ。
