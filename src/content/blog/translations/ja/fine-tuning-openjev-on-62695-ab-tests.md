新しい意思決定モデルをベースにした公開プロジェクトがおよそ300件あって、そのうち「スコアリングとランキング」を扱うもの（26件）を全部チェックしてみたところ、例外なくどれもモデル自身にどう思うか尋ねるだけでスコアリングしていた。この記事を8つの品質軸で採点して、このコピーのセンスを評価して、このドキュメントが関連しているか判定して、といった感じだ。

それってデータと言えるのだろうか？単にモデルの意見に数字を貼り付けただけで、ジャンル全体がその上に成り立っていると言わざるを得ない。

そこで、実際に誰かが計測した結果を使ってモデルを訓練してみた。試してみたい人のために重みも公開している。**[`NovusEdge/vera-deberta-v3-large`](https://huggingface.co/NovusEdge/vera-deberta-v3-large)**、Apache 2.0、パラメータ数435M、1回のフォワードパスで短い説得力のあるテキストをスコアリングする。ベースは[`com-kotobalabs/open-jev-deberta-v3-large`](https://huggingface.co/com-kotobalabs/open-jev-deberta-v3-large)で、これは型付きの意思決定データで事前学習されたDeBERTa-v3-largeだ。

| 指標 | 本モデル | 公開SOTA | 人間 |
|---|---|---|---|
| ペアワイズ正解率（未学習スプリット） | **0.812** | 0.544 | 約チャンスレベル |
| クリーンなペアのみ | **0.797** | - | - |
| 最悪のバリアントの回避率 | **90.3%** | - | - |

このモデルは32,487件のランダム化された見出し実験から得られた62,695件の実A/Bテストアームで訓練されており、上の数字はすべてモデルが見たことのないスプリットからのものだ。ここに至るまでの経緯は以下に書いた。最初のベンチマークがまったく何も測定していなかった件も含めて（正直まだちょっと根に持っている）。

## セットアップ

実はこれにうってつけのデータセットが存在していて、2021年からずっと公開されていた。2013年1月から2015年4月にかけて、Upworthy（そう、あの「この後どうなったか信じられない」でおなじみのUpworthy）は見出しに対して32,487件のランダム化A/Bテストを実施した。リアルのトラフィック、リアルのランダム化、5億3800万回の割り当て。そしてコーネル大学がそのすべてをCC BYライセンスの[Upworthy Research Archive](https://osf.io/jd64p/)として公開したのだ。すべての見出しバリアント、すべてのインプレッション、すべてのクリックが含まれている。

これは短い説得力のあるテキストとしてはグラウンドトゥルースに最も近い。書かれたテキストがあり、本物の人間がそれを見たときに何が起きたかが記録されており、割り当てがランダムだったため、それらを比較することに本質的な意味があるからだ。

構成は次のとおり。ModernBERT-largeに回帰ヘッドを付け、ターゲットは各テスト自体の平均を中心とした縮小ロジットクリック率とした。ちなみに中心化は重要で、クリック率のばらつきの大半は*記事そのもの*に起因しており、見出しだけではそれを説明できない。そのため実際に予測したいのは、あるアームがそれが属するテストの平均からどれだけ離れているかになる。その上で平均へのベータ二項縮小を行い、600インプレッションのアームはほぼ事前分布として、20,000インプレッションのアームはほぼ確実な証拠として扱う。

L4 1枚で25分、費用は約40セント。2015年1月以降のデータをすべてホールドアウトしてテストしたところ、**ペアワイズ正解率は0.704**を記録した。

比較のために挙げると、このデータセットでの公開されているSOTAは[0.544](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0281682)で、これはトロントの研究グループが24,333ペアに対して人手で作った言語特徴量を使ったものだ。彼らの論文では、この問題は「単なるサンプルサイズの問題ではなく本質的に困難」と結論づけている。同じタスクを与えられた人間のスコアはチャンスレベル程度で、文献にあるLoRAを適用したLlama-3-8Bのスコアは0.469と、チャンスレベル*以下*だった（笑）。

40セントで公開数値を16ポイント上回ったわけだ。当然、私は「見出しのシグナルは2年間のドリフトに耐える」というタイトルで記事を書いた。

## しかし

そのタイトルで主張していたのは、シグナルが*ドリフト*を乗り越えるということだった。訓練データは2013〜2014年でテストセットは2015年だったにもかかわらず、精度がほとんど落ちなかったからだ。2年間でインターネットのカルチャーが移り変わってもモデルは意に介さなかった、というわけだ。これが本当なら素晴らしい発見だし、重要でもある。最終的な目的はこれをメールの件名に適用することであり、同じ媒体内で2年の経過に耐えられないなら、まったく別のメディアへの移行に耐えられるはずがないからだ。

このアーカイブには3つのスプリット（探索用、検証用、ホールドアウト）が用意されており、私は検証用（confirmatory）で訓練とテストを行っていた。念のため、そしてすでに「分かっている」ことを再確認するつもりで、残りの2つのスプリットでも同じ重みを評価してみた。

```
confirmatory 2015:  0.704
holdout:            0.637
exploratory:        0.624
```

最高だ。

一度も触れていなかった2つのスプリットは、*すべての効果サイズ階層*において0.013の範囲で一致しており、どちらも私の見出しの数値が7ポイント水増しされていたことを告げていた。

![Upworthyアーカイブの3つのスプリットにおけるペアワイズ正解率。検証用2015のラインは、互いに近似しているホールドアウトと探索用を大きく上回っている。](/assets/img/blog/decision-models/splits.png)

赤い線が私が投稿した数値で、その下にある2本の線が真実だ。

## 横にしか進まないタイムマシン

そこで今回はアーカイブのドキュメントをちゃんと読み直してみたところ、アーカイブはテストを各スプリットに**ランダム**に割り当てていたことが判明した。時系列ではなく、ランダムにだ。

![2つのバー。1つ目は訓練からテストへの綺麗な時系列スプリット。2つ目は実際の構造で、全期間にわたって訓練ブロックとテストブロックが交互に配置されている。](/assets/img/blog/decision-models/split-structure.png)

| スプリット | アーム数 | 日付範囲 | 2015年以前の割合 |
|---|---|---|---|
| 検証用（confirmatory） | 51,891 | 2013-01-24 → 2015-04-30 | 83.5% |
| ホールドアウト | 11,231 | 2013-01-24 → 2015-04-29 | 82.8% |
| 探索用（exploratory） | 10,804 | 2013-01-26 → 2015-04-29 | 83.8% |

3つのスプリットはすべて同じ期間を同じ割合でカバーしている。つまり、ホールドアウトでスコアを計測したとき、テストしていたデータの83%は*訓練期間の内側*のものだった。同じ時代、同じ文体、同じ環境で、ただモデルが見たことのないテストだっただけなのに、2015年の末尾データよりも*低い*スコアを出したのだ。

見方を変えれば少し面白い話で、このモデルにとって時間の経過によるコストはほぼゼロだったのに対し、同じ期間の未知のテストによるコストは7ポイントだった。私が慎重に構築したドリフトテストはずっとテストの個別性を測定していただけで、時間的一般化の皮を被っていたにすぎなかったのだ。

私は横にしか進まないタイムマシンを作ってしまっていた。

## 2つの仮説、どちらも逆だった

次に思い浮かぶのは当然リーク（情報漏洩）だ。Upworthyは同じ記事に対して何十もの見出しバリアントを書き直していたため、*テスト*をランダムに分割すると、1つの記事のリライトが3つのスプリットすべてに散らばり、ホールドアウトには訓練テキストの類似コピーが大量に含まれることになる。

そこで簡単な転置インデックスを作って、各評価見出しとモデルが実際に学習した38,950件の見出しとの間の最大Jaccardトークン重複度を測定してみた（完全一致文字列マッチングでは650件中5件しか共通見出しが見つからず、そう、私はそれだけでリークは「除外された」と判断していたのだ）。

| 評価セット | n | 重複度≥0.9 | 中央値 |
|---|---|---|---|
| 検証用 2015 | 1,300 | 0.5% | 0.227 |
| ホールドアウト | 4,274 | **30.5%** | 0.300 |

30%。2015年のデータと比べて60倍も汚染されていたのに、スコアは**低かった**のだ。

したがってリークではこのギャップを説明できない。完全に逆方向の結果になっている。むしろ類似コピーを取り除けば、真っ当なホールドアウトの数値は0.637よりも*悪くなる*はずだ。ペアごとのスコアを出力してスライスし、これも確認してみたところ、真にクリーンなペアに対してモデルは0.646と、わずかに*良い*スコアを出した。つまり類似の重複データは何の役にも立っていなかったのだ。

ではラベルノイズだろうか？もしホールドアウトのペアのインプレッション数が少なければ、観測された勝者が真の勝者ではない可能性が高くなり、スコアの上限が抑えられてしまう。

| 評価セット | インプレッション中央値 | zスコア中央値 | CTR比中央値 |
|---|---|---|---|
| 検証用 2015 | 2,462 | 2.37 | 2.24 |
| ホールドアウト | 3,096 | 2.64 | 1.99 |

これも逆だった（笑）。ホールドアウトのペアの方がインプレッション数が*多く*、zスコアも*高い*ため、そのラベルの方が信頼性が高いのだ。たしかに2015年のセットはCTR比の中央値の開きが大きく（1.99に対して2.24）、ペアの識別がより容易だったのは事実だが、7ポイントもの差を説明できるほどではない。

そこでドキュメントに「原因不明」と書いて先へ進むことにした。0.63というのが実際の数字であり、2つの独立したスプリットがそれで一致していて、乖離している1つが外れ値だ。その理由は分からない。

## 本当に重要だった部分

自分の目玉結果を打ち砕いた後、少なくともアブレーション実験くらいはちゃんとやろうと考えた。

データ量を増やすのが勝つだろうと予想していた。それが退屈ながら順当な事前予想だからだ。62,695のアームがあるのだから、第3のスプリットを投入すれば性能は上がるはずだ。そこで、探索用スプリットを訓練に追加する実験と、損失関数を変更する実験の2つを用意し、どちらも同じ2,137組のホールドアウトペアで評価した。

```
Phase 0        confirmatory       MSE              0.637
more-data      expl+confirmatory  MSE              0.724
rank           confirmatory       Bradley-Terry    0.775
rank+more      expl+confirmatory  Bradley-Terry    0.787
```

![アブレーション結果。データの追加でベースラインから0.087向上。Bradley-Terryへの切り替えで0.138向上し、最良の実行では0.812に達した。](/assets/img/blog/decision-models/ablations.png)

訓練データを28%増やしたことで**+0.053**となり、損失関数を変更したことで**+0.107**となった。3エポックではなく2エポック、しかも小さい方の訓練セットで実行したにもかかわらず、2倍の差をつけて勝ったのだ。

振り返ってみれば当たり前の話で、一番嫌なタイプの当たり前だった。ベンチマークは*ペアワイズ正解率*（2つの見出しが与えられたときに勝者を選ぶ）なのに、私はクリック率に対して回帰を行っていた。つまり、指標の代理変数（プロキシ）を最適化しておきながら、その指標自体で自分を評価していたわけだ。

[Bradley-Terry](https://en.wikipedia.org/wiki/Bradley%E2%80%93Terry_model)は対象そのものを最適化する。1つのテスト内のすべてのアームのペアに対して`logsigmoid(score_winner - score_loser)`を最大化し、インプレッションが少ない方のアームの対数インプレッション数で重み付けする。比較の信頼性はインプレッションが少ない側に依存するからだ。私の38,950件の訓練アームは、テスト内における63,597ペアに変換された。

同じモデル。同じデータ。異なる目的関数。14ポイントの差。

興味本位でModernBERT-*base*（パラメータ数は3分の1）も動かしてみたところ0.761を記録した。そのため、性能の大部分はモデルサイズではなく目的関数とデータに起因していることがわかる。CPUで動かしたい場合には嬉しい結果だ。

そして、危うく見落とすところだったモデルがある。意思決定タスクで事前学習されたDeBERTa-v3-largeバリアントを試したところ、4,804ステップの間ずっとぴったり`-log(0.5)`のままで、スコアはチャンスレベルそのままの0.519だった。

これを見て「DeBERTaはダメだ」と解釈して切り捨てるのは簡単だし、私も危うくそうしかけた。しかし、「当て推量をしている」ことを意味するまさにその値で損失曲線が*完全に*フラットになるというのは非常に特異な兆候であり、モデルが学習に失敗しているときの様子とは違う。エンコーダのロードも正常に行われており、新しく初期化されたのは分類器とプーラーだけだったので、挙動としては想定内だった。

原因は学習率だった。DeBERTa-v3-largeはModernBERTが好む2e-5では[不安定になることで有名](https://github.com/microsoft/DeBERTa/issues/77)で、6e-6あたりを求めていたのだが、私は当然のように両方に同じ設定を使っていたのだ。

6e-6で再実行したところ、損失は0.709 → 0.682 → 0.620 → 0.360と推移し、プロジェクト全体で最高となる**0.812**で終了した。ModernBERTを2.5ポイント上回り、最高信頼度層では0.913を記録した。

この時点では自分を信用していなかったので、類似重複のスライスでもテストしてみた。真にクリーンなペア（訓練データに似たものが一切ないデータ）において、ModernBERTの0.769に対して**0.797**を記録した。また、暗記によるスコア差もModernBERTより*小さく*、かつ高いスコアを出していた。これは記憶（リコール）で勝っているモデルの挙動とは正反対だ。

つまり、システムはずっと正常に機能していたのに、私が数値を1つ間違えていただけだった。

## しかし0.812は実際*何を意味する*のか

正直なところ、人間にとっては何も意味しない。それが主張としてのペアワイズ正解率の問題点だ。順序が正しいことしか分からず、その大きさについては何も教えてくれない。2つの見出しを81.2%の確率で正しく順序付けできることは、それらの実際の差次第で莫大な価値にもなれば無価値にもなる。

そこで、実際にそれを送信する人がどう感じるかを測定してみた。テストごとにモデルが最高スコアをつけたアームを取り出し、その実際のクリック率をそのテスト内の全アームの平均と比較する。モデルがなければ特定のバリアントを選ぶ理由はないため、送信した可能性のあるものの平均が真っ当な反事実（対照群）になる。

| | CTR |
|---|---|
| テスト平均（モデルなし） | 1.20% |
| モデルの選択 | 1.42% |
| オラクル（完璧な選択） | 1.60% |

これは2,140件のテスト全体で**+18.3%の相対クリック率向上**を意味するが、この数値はすぐに取り下げなければならない。

### リフトの数値は一般化しない

18.3%というのはUpworthy特有の事実だ。彼らの1.20%というベースレートや、ライターがバリアント間にどれだけの差を設けたかに依存している。これをクリック率2.5%でバリアントの差が小さいB2Bニュースレターに適用すれば数値は変わるし、どちらに転ぶか予測もつかない。

一方で、単一テスト内の比率であるものは*一般化*する。

| 指標 | 値 |
|---|---|
| 最悪のバリアントの回避率 | **90.3%** |
| テスト平均を上回る割合 | 76.6% |
| 実際に最良のバリアントを選ぶ割合 | 47.7% |
| 獲得できた改善幅（中央値） | 89.2% |
| スピアマンの順位相関係数（スコア対クリック率） | 0.526 |

**私が自信を持って保証できるのは90.3%という数字だ。** 最悪のコピーを送ってしまうことをほぼ防いでくれる。これはベースレートやオーディエンス、媒体が変わっても、「+18.3%」という数字とは違って通用する。また、通常4〜5個のアームがある中でTop-1が47.7%というのは、チャンスレベルの約2.2倍だ。

ただし、この中の1つは少し紛らわしい。獲得できた改善幅の中央値は89.2%（四分位範囲は5%〜100%）だが、全テストでプールした全体値は55.4%になる。モデルには二峰性があり、大半のテストでは可能な改善幅をほぼすべて獲得できる一方で、ごく一部のテストではほとんど獲得できず、それが全体の数値を引き下げている。そのため、中央値だけを引用すれば過大評価になり、プールした数値だけを引用すれば典型的なケースを過小評価してしまう。

そこで、スコアに雰囲気ではなく単位を持たせるために、上に[アイソトニック回帰](https://en.wikipedia.org/wiki/Isotonic_regression)を適用した。ここでアイソトニック回帰が適しているのは、単調性（スコアが高いほどクリック率が高い）のみを仮定しているためだ。これはBradley-Terryが保証する内容と完全に一致し、かつ保証するのは文字通りそれだけだからだ。パラメトリックな手法を使うと、モデルが約束していない構造を勝手にでっち上げることになってしまう。1つのテスト内のアームは同じ記事を共有しており独立していないため、信頼区間はアームではなく*テスト*単位のブートストラップから算出している。

| スコア | ベース比 | 90%信頼区間 |
|---|---|---|
| −2.72 | **−19.1%** | [−0.252, −0.209] pp |
| −1.06 | −8.2% | [−0.111, −0.086] pp |
| −0.20 | −0.7% | [−0.023, −0.000] pp |
| +0.56 | +3.7% | [+0.030, +0.056] pp |
| +1.62 | +11.1% | [+0.115, +0.147] pp |
| +2.82 | **+21.8%** | [+0.231, +0.274] pp |

![キャリブレーション曲線。ベースラインに対するクリック率はモデルスコアとともに単調増加し、90%信頼区間がゼロを跨ぐのは中央付近のみ。](/assets/img/blog/decision-models/calibration.png)

送信しうる最悪の件名と最良の件名の間には41ポイントの開きがある。そして中央の行を見ると、区間がゼロを跨いでいる。これはモデルが「これら2つは同じ見出しだからコイントスと同じだ」と正しく判断していることを意味する。*分からない*と言えるスコアラーは、それが言えないものよりはるかに価値がある。

## さて、ここで台無しにする話

上記の数値はすべて、とある1つのメディアにおける2013〜2015年のバイラル系SNS見出しから得られたものだが、私が実際に作りたいのはメールの件名をスコアリングするものだ。

これらはまったくの別物だ。オプトインした4,000人に届くB2Bニュースレターは、「この子供がたった一言でワクチン反対論を論破した」といった見出しとは共通点がほとんどない。メディアも違い、読者層も違い、年代も違い、すべてが異なる。

そこで実際に計測された送信結果を含む公開メールデータを探してみたが、存在しなかった。

| ソース | 規模 | 入手性 |
|---|---|---|
| Return Path 件名調査 | 900万件の件名 | プロプライエタリ、2015年、未公開 |
| Belkins B2Bコーパス | 550万通のメール | 集計統計のみ |
| Yahoo (IEEE 7004277) | 10万件以上の件名、数十億インプレッション | プロプライエタリ |
| OracleのNLORP論文 | 300件の件名 | Googleからスクレイピング、数値は未計測 |
| Kaggleの各種「メールキャンペーン」データ | まちまち | モックまたは合成データ |

そのうちの1つはOracleの主任データサイエンティスト2名によるarXivの論文で、そのデータセット全体が「Google検索を通じて複数のインターネットソースから収集された、特別セールのメールの300件以上の異なる件名」だった。彼らを馬鹿にしているわけではなく、実際に世の中にあるのがそれだけなのだ。

集計結果（6〜10語が最もパフォーマンスが良い、開封には21〜40文字が良い、数字を入れると数ポイント上がるなど）はあちこちで見かけるが、送信ごとの結果データはどこにもなく、どれもモデルの訓練には使えない。

## そして取り組み全体の意味が変わる

第三者の意見によって打ち砕かれるまで、私は都合の良いストーリーを自分に言い聞かせていた。そのストーリーとは、*アーキテクチャはコモディティであり、持続的な資産となるのはプロプライエタリな結果ラベルである*というものだ。前半は正しいが後半はナンセンスだ。なぜなら私はプロプライエタリなラベルを*持っていない*からだ。Upworthyのデータは公開されており、GPUさえあれば誰でも週末にコーヒー代以下のコストで私の0.812を再現できる。重みをそのまま公開している理由の一部もそこで、4ドルしかかかっていないものに参入障壁があるふりなどできない。

私が実際に持っているのは実績（クレデンシャル）だけだ。真の資産とは本番トラフィックでの継続的な計測ループのことであり、それはまだ存在しない。

これはある意味で状況をクリアにしてくれた。本物がどこにあるかを教えてくれたからだ。私が必要としているデータはメール配信サービス（ESP）の内部で眠っている。A/Bテスト機能を備えたすべてのESPには、結果が計測された何百万もの件名実験データがあるのに、それを使って何かを訓練しているところはほぼ皆無だ。つまり、私に必要なのは新しいモデルヘッドでも別のベンチマークでもなく、ログを持っている誰か1人なのだ。

## これが一般化できる先

レシピ自体は一行に収まるほど退屈なものだ。計測された結果が存在するならそれを学習させ、モデルに意見を聞くのはやめろ、ということだ。

言う価値があるのは、そうした結果がすでにどこに存在しているかという点だ。あなたの会社がこれまでに実施したすべてのA/Bテストは、ラベルが付けられ結果が紐づいた状態で、何かの実験プラットフォームの中で眠っている。Optimizely、Statsig、LaunchDarklyなど何を使っていても、「この5つを試してこれが勝った」という何年分ものデータがあり、誰もそれを使って何も訓練していない。

候補のセットがあり、下流で数字が得られる場所ならどこでも同じことが当てはまる。

| 意思決定 | すでに手元にあるラベル |
|---|---|
| 件名、見出し、プッシュ通知のコピー | 開封数、クリック数 |
| サポートのマクロ選択 | エスカレーションなしで解決したか |
| 検索結果の再ランキング | ユーザーが受け入れた検索結果 |
| エラーメッセージの文言 | 自己解決したか、チケットを切られたか |
| 商品リストのタイトル | コンバージョン |
| エージェントのツール選択 | 一連の軌跡が成功したか |

エージェントを作っているなら最後の行は面白いところだ。Jevの3つのプリミティブはchoice、score、noulであり、この記事の内容はすべて`score`に関するものだが、意思決定の後に何が起きたかが記録されている場所であれば、どこでも同じ手法が`choice`にも適用できる。ほとんどのエージェントルーティングにおいては、まだ誰も記録していないが。

ただし、これらすべてに対する率直な限界として、私にはデータポイントが1つしかない。結果に基づいた訓練がゼロショットの判定を大きく上回ったのは*1つのタスクにおいて*であり、その差が他の場所でも維持されるかどうかは未検証だ。だから数字そのものではなく、方向性に賭けるべきだろう。

## VERA

**V**ariant **E**valuation from **R**eal **A**nalytics（実績データによるバリアント評価）。すべてのモデルにはちょっとしたバクロニムが必要だからね。

**[`NovusEdge/vera-deberta-v3-large`](https://huggingface.co/NovusEdge/vera-deberta-v3-large)**、Apache 2.0。

```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer

tok = AutoTokenizer.from_pretrained("NovusEdge/vera-deberta-v3-large")
model = AutoModelForSequenceClassification.from_pretrained(
    "NovusEdge/vera-deberta-v3-large")

# Score a set of candidates for ONE piece of content. Higher wins.
enc = tok(candidates, padding=True, truncation=True, max_length=64,
          return_tensors="pt")
scores = model(**enc).logits.squeeze(-1)
```

スコアは単一の数値としてではなく、必ずセットとして解釈してほしい。訓練のターゲットはテスト自身の平均からの偏差だったため、スコア単体では何の意味も持たない。1回の送信のために書いた3〜6個のバリアントを与えると、それらをランク付けしてくれる。スコアを期待リフト量にマッピングするキャリブレーターも同梱されている。

435Mが重すぎる場合は、CPU向けのサイズのものも公開している。ModernBERT-baseは3分の1のパラメータ数で0.761を記録している。

## できないこと

メールへの転用、あるいは少なくとも転用できるかどうかは私には分からない。ここにあるものはすべて、とある1つのメディアにおける2013〜2015年のバイラル系SNS見出しであり、あなたのニュースレターは「この子供がたった一言でワクチン反対論を論破した」とはほとんど共通点がないはずだ。

もしニュースレターを運営していて、開封率やクリック率が計測された過去の送信データをお持ちなら、ぜひ確かめてみたいので連絡してほしい。データはもちろんあなたのものだ。

## まとめ

この分野のオープンウェイトモデルの1つは、自身の型付き意思決定ベンチマークでゼロショット時に0.362を記録しており、これは多数派クラスのベースラインである0.461を下回っている。つまり、使い物にするにはタスク固有のファインチューニングが必要であり、アーキテクチャ単体では大したことはできない。

そして0.544から0.812への飛躍も、賢巧なモデリングによるものではなかった。その3分の2は評価指標に合わせた損失関数の選択によるもので、残りは実際に起きた結果が計測された62,695行のデータのおかげだ。だから、もしモデルに意見を聞いてデータをラベリングしているなら、まずはグラウンドトゥルースを探しに行ってみてほしい。それはおそらく、すでにどこかに転がっているはずだ。
