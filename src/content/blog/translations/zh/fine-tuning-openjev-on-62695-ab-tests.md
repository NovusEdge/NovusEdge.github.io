现在大概有 300 个基于新决策模型构建的公开项目，我翻了翻其中属于“打分和排序”类的（一共 26 个），发现它们每一个给东西打分的方式，都仅仅是去问模型怎么看。让它从八个质量维度给这篇文章打分、评估这段文案的品味、判断这篇文档是否相关，你懂的。

但这说实话算什么数据？这不过是给模型的个人观点强行贴了个数字而已，而且老实讲，整个品类的项目全都是搭在这一套上面的。

所以我用别人实际测量出来的真实结果训练了一个模型，如果你想玩玩看的话，权重已经开源了：**[`NovusEdge/vera-deberta-v3-large`](https://huggingface.co/NovusEdge/vera-deberta-v3-large)**，Apache 2.0 协议，4.35 亿参数，单次前向传播，用来给简短的说服性文案打分。它的基座是 [`com-kotobalabs/open-jev-deberta-v3-large`](https://huggingface.co/com-kotobalabs/open-jev-deberta-v3-large)，本身是在类型化决策（typed decisions）上预训练过的 DeBERTa-v3-large。

| 指标 | 本模型 | 纯随机概率 | Gemini 3.1 Pro |
|---|---|---|---|
| 未见数据集上的成对准确率 | **0.812** | 0.546 | 0.751 |
| 仅纯净成对样本 | **0.797** | 0.546 | - |
| 从 4-5 个变体中选出最优 | **47.7%** | 23.0% | - |
| 避开最差变体 | **90.3%** | 77.0% | - |
| Reddit 标题对（域外数据） | 0.522 | 0.500 | - |

它是在来自 32,487 次随机标题实验的 62,695 个真实 A/B 测试变体上训练出来的，上面列出的每一个数字都来自模型从未见过的拆分数据集。下面会详细讲讲它是怎么做到的，包括我最初那个基准测试测出来的东西根本毫无意义的那段糗事（没错，我现在想起来还是有点不爽）。

## 实验设置

事实证明，这个任务刚好有一份完美的数据集，而且它从 2021 年起就一直公开放在那儿了。在 2013 年 1 月到 2015 年 4 月期间，Upworthy（没错，就是*那个*著名的标题党鼻祖 Upworthy，“接下来发生的事绝对让你不敢相信”的那家）针对他们的标题跑了 32,487 次随机 A/B 测试，真实的流量，真实的随机分配，5.38 亿次曝光分配。后来康奈尔大学把这整套数据以 CC BY 协议公开发布为 [Upworthy Research Archive](https://osf.io/jd64p/)。包含了每一个标题变体、每一次曝光展示、每一次点击。

这大概是你在简短说服性文本领域能拿到的最接近真实事实（ground truth）的数据了。

所以做法是：ModernBERT-large 加上一个回归头，预测目标是以每次测试自身的均值为中心、经过收缩的 logit 点击率。顺便说一句，中心化（centring）非常关键，因为点击率的绝大部分方差是由*文章本身*决定的，标题根本解释不了这部分差异，所以你真正想预测的，其实是某个变体相对于它所在测试的均值偏离了多少。接着用 Beta-二项收缩（beta-binomial shrinkage）向该均值收缩，这样只有 600 次曝光的变体主要算作先验，而有 20,000 次曝光的变体才主要算作有效证据。

在单张 L4 上跑了 25 分钟，花了大概 40 美分。我把 2015 年 1 月之后的所有数据留作测试集，跑完测下来得到了 **0.704 的成对准确率**。

作为对比，之前在未过滤配对上公开发表的最好成绩是 [0.544](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0281682)，来自多伦多大学的一个团队，他们使用的是人工设计的语言学特征，并且其论文得出的结论是，这个问题“本质上就很困难，而不仅仅是样本量的问题”。我稍后会回过头来聊聊为什么这个 0.544 看起来是个更糟糕的参照物，而且在后文里我也不再引用别人的数字，而是自己亲自跑了对比。

比那个成绩高出了 16 个点，只花了 40 美分。于是我顺理成章地写好了结论：“标题信号在两年的时间漂移中依然有效。”

## 然而

我那个标题里的论点是信号能够抗住*时间漂移*，因为训练数据是 2013 到 2014 年的，测试集是 2015 年的，而准确率几乎没怎么动，就好像经历了两年互联网文化的变迁，模型完全不在乎一样。如果这是真的，那确实是个重大发现，这一点之所以重要，是因为做这个模型的终极目标是把它用在邮件主题行上，如果它连同一家媒体内两年的时间跨度都抗不过去，那就绝对不可能跨越到完全不同的媒介上去。

这份档案分成了三个子集（exploratory、confirmatory、holdout），而我之前是在 confirmatory 上训练和测试的。于是多半出于严谨起见，同时也满心期待着能印证我自以为已经“知道”的结论，我用同样的权重去跑了另外两个子集的评分。

```
confirmatory 2015:  0.704
holdout:            0.637
exploratory:        0.624
```

很好。

两个我完全没碰过的子集，在*每一个效应量层级*上的差异都在 0.013 以内，而且它们俩都告诉我：我之前引以为傲的那个成绩被虚夸了整整 7 个点。

![Upworthy 档案三个拆分子集上的成对准确率。confirmatory 2015 的曲线远高于 holdout 和 exploratory，而后面两者彼此高度吻合。](/assets/img/blog/decision-models/splits.png)

## 一台只能横向穿越的时光机

于是我这次老老实实地仔细读了一遍数据集的文档，结果发现：这份档案给各个拆分子集分配测试是**完全随机的**。根本不是按时间顺序划分的，而是随机分配的。

![两个柱状图。第一个展示了干净的时间拆分，先训练后测试。第二个展示了真实的结构：整个时间段内训练块和测试块是交错在一起的。](/assets/img/blog/decision-models/split-structure.png)

| 数据集划分 | 变体数量 | 日期范围 | 2015 年之前的占比 |
|---|---|---|---|
| confirmatory | 51,891 | 2013-01-24 → 2015-04-30 | 83.5% |
| holdout | 11,231 | 2013-01-24 → 2015-04-29 | 82.8% |
| exploratory | 10,804 | 2013-01-26 → 2015-04-29 | 83.8% |

所有三个子集都以相同的比例覆盖了相同的日期范围，这意味着当我在 holdout 上打分时，我测试的内容有 83% 实际上来自*训练期内部的时间段*。同样的时代背景，同样的媒体风格，同样的一切，只不过是模型没见过的测试组而已，但它在那上面的表现居然比在 2015 年的尾部数据上*还要差*。

反过来想，说实话还挺搞笑的：时间跨度对这个模型几乎毫无影响，但同一时期的未见测试却让它掉了 7 个点。我精心设计的漂移测试，从头到尾测出来的其实都只是“测试组身份识别”，只不过套了一层时间泛化能力的外皮而已。

我造出了一台只能横向移动的时光机。

## 两个假设，结果全都猜反了

接下来很自然的想法就是数据泄漏。Upworthy 会为同一篇文章重写几十种不同的标题变体，因此如果你按*测试*随机拆分，那么同一篇文章的改写标题就会散落到所有三个拆分子集中，holdout 里面理应充斥着与训练文本高度相似的副本。

我随手写了个倒排索引工具，用来计算每个评估标题与模型实际拟合过的 38,950 个标题之间的最大 Jaccard token 重合度（之前用精确字符串匹配在 650 个样本里找到了 5 个相同标题，没错，我当时凭这个就宣称“排除了数据泄漏”）。

| 评估集 | n | 重合度 ≥0.9 | 中位数 |
|---|---|---|---|
| confirmatory 2015 | 1,300 | 0.5% | 0.227 |
| holdout | 4,274 | **30.5%** | 0.300 |

30% 的重合度，污染程度是 2015 年尾部数据的 60 倍，但它的得分反而**更低**。

所以数据泄漏根本解释不了这个差距，因果方向完全反了；真要说的话，这意味着一旦你剔除了这些近似副本，真正的 holdout 分数应该比 0.637 *还要更差*。我也验证了这一点，把每个样本对的分数导出来切片分析，在真正干净的配对上，模型的得分是 0.646，反而略微*好了一点点*，所以那些近似副本根本没给它带来任何优势。

行吧，那难道是标签噪声的问题？也许 holdout 的样本对曝光量比较少？

| 评估集 | 曝光量中位数 | z 评分中位数 | 点击率比值中位数 |
|---|---|---|---|
| confirmatory 2015 | 2,462 | 2.37 | 2.24 |
| holdout | 3,096 | 2.64 | 1.99 |

又猜反了，笑死。holdout 样本对的曝光量*更多*，z 评分也*更高*。2015 年的数据集确实有着更大的点击率比值中位数（2.24 对 1.99），所以它的样本对确实更容易区分，这是事实，但也远远撑不起 7 个点的差距。

于是我在文档里写下了“未解之谜”，然后继续往前走。0.63 就是真实数字，两个独立的子集结论一致，产生分歧的那个才是异常值，至于为什么会这样，我也说不出个所以然。

**！！硬核技术信息倾倒预警 :3 ！！**

## 真正起作用的部分

在推翻了自己最初的标题结论之后，我觉得至少应该把消融实验认认真真跑一遍。

我原本以为加数据肯定会赢，因为这是显而易见的老生常谈嘛：手头有 62,695 个变体，把第三个子集扔进去，数据量变大就行了。所以我配置了两次训练，一次是把 exploratory 子集加进训练集，另一次是更换损失函数，两者都在相同的 2,137 个 holdout 样本对上进行评估。

```
Phase 0        confirmatory       MSE              0.637
more-data      expl+confirmatory  MSE              0.724
rank           confirmatory       Bradley-Terry    0.775
rank+more      expl+confirmatory  Bradley-Terry    0.787
```

![消融实验结果。增加数据比基线提升了 0.087；切换到 Bradley-Terry 提升了 0.138，最好的实验达到了 0.812。](/assets/img/blog/decision-models/ablations.png)

增加 28% 的训练数据带来了 **+0.053** 的提升，而更换损失函数带来了 **+0.107** 的提升，而且这还是在只跑了 2 个 epoch 而不是 3 个、并且使用了更小训练集的情况下跑出来的，提升幅度依然翻倍碾压了前者。

事后看来这其实再明显不过了，属于那种最让人拍大腿的显而易见。基准测试考核的是*成对准确率*（给出两个标题，选出胜者），而我之前做的是对点击率做回归，也就是说我一直在优化这个指标的代理变量，然后拿实际指标来给自己打分。

[Bradley-Terry](https://en.wikipedia.org/wiki/Bradley%E2%80%93Terry_model) 模型优化的才是真正要考核的目标。对于单次测试中的每一对变体，最大化 `logsigmoid(score_winner - score_loser)`，并用曝光量较小的那个变体的 log 曝光量进行加权。我那 38,950 个训练变体转化成了 63,597 个同测试内的配对。

同样的模型，同样的数据，换了个目标函数，涨了 14 个点。

出于好奇我还跑了 ModernBERT-*base*（参数量只有三分之一），它也达到了 0.761。所以这其中的大部分提升来自于目标函数和数据，而不是模型规模，如果你以后想在 CPU 上跑这套东西的话，这绝对是个好消息。

接下来还有一个险些被我错过的插曲。我尝试了一个在决策任务上预训练过的 DeBERTa-v3-large 变体，结果在全部 4,804 步训练中，它的 loss 纹丝不动地停在 `-log(0.5)`，得分 0.519，跟纯随机瞎猜毫无区别，完全是一条直线。

遇到这种情况很容易直接得出“DeBERTa 不行”的结论然后直接略过，我当时也差点就这么做了。但是一条在代表“纯瞎猜”的精确数值上*完全*平坦的 loss 曲线，是一个极其特殊的特征，这根本不是一个模型学得不好的表现。encoder 加载得也很正常，只有分类头和 pooler 是全新初始化的。

问题出在学习率上。DeBERTa-v3-large 在 ModernBERT 跑得很顺的 2e-5 学习率下是[出了名的不稳定](https://github.com/microsoft/DeBERTa/issues/77)，它需要的学习率更接近 6e-6，而我图省事对两者用了同一套配置，毕竟谁不想省事呢。

用 6e-6 重新跑了一遍，loss 变成了 0.709 → 0.682 → 0.620 → 0.360，最终成绩定格在 **0.812**，比 ModernBERT 高出 2.5 个点，在最高置信度层级上更是达到了 0.913。

在这个模型上也跑了近似副本的切片测试，因为到了这一步我已经有点疑神疑鬼了。在完全纯净的配对上（没有任何与训练集相似的内容），它拿到了 **0.797**，相比之下 ModernBERT 是 0.769。而且它的记忆差距（memorization gap）在得分更高的同时比 ModernBERT *还要小*，这跟靠死记硬背取胜的模型表现完全相反。

所以系统从头到尾运行得都没问题，只是我之前把一个超参数搞错了而已。

## 但 0.812 到底*意味着什么*

老实说，对人类来说它没有任何直观意义。这就是把成对准确率作为宣传口号的问题所在：它只能说明排序是对的，却完全没有告诉你差距有多大。以 81.2% 的准确率排对两个标题的顺序，根据两者实际差距的大小，可能价值千金，也可能分文不值。

所以我去衡量了一个真正要发文案的人会有什么实际感受。对于每一次测试，取出模型打分最高的那个变体，拿它的真实点击率去对比该测试中所有变体的平均点击率。因为在没有模型的情况下，你没有任何理由偏向某一个变体，所以你可能发送的那些文案的平均值才是诚实的反事实基准。

| | 点击率 |
|---|---|
| 测试均值（无模型） | 1.20% |
| 模型的选择 | 1.42% |
| 理想上限（上帝视角选最优） | 1.60% |

在 2,140 次测试中，这意味着 **+18.3% 的相对点击率提升**，不过我马上就得把这盆冷水浇回你头上。

### 提升幅度这个数字是无法直接迁移的

18.3% 是只属于 Upworthy 的事实。它取决于他们 1.20% 的基准点击率，以及他们的写手在不同变体之间拉开的差距有多大。所以如果把它用在基准点击率为 2.5%、变体之间差异更小的 B2B 新闻通讯（newsletter）上，这个数字就会发生变化，而且变化的方向我根本无法预测。

真正*能够迁移*的，是单次测试内部的各种比率指标：

| 指标 | 数值 |
|---|---|
| 避开最差变体 | **90.3%** |
| 击败测试平均水平 | 76.6% |
| 选中真正的最优变体 | 47.7% |
| 捕获的提升空间（测试中位数） | 89.2% |
| Spearman 相关系数（得分 vs 点击率） | 0.526 |

**90.3% 是我敢真正打包票的数字。** 它几乎绝不会让你发出你写出来的最烂的那篇文案，而且这种能力在基准转化率、受众和媒介发生变化时依然成立，不像“+18.3%”那么脆弱。而在通常包含 4 到 5 个变体的情况下达到 47.7% 的 top-1 命中率，大约是纯随机概率的 2.2 倍。

不过这里面有个指标耍了点小花招。捕获的提升空间中位数是 89.2%，四分位距在 5% 到 100% 之间，而在所有测试上汇总算下来是 55.4%。模型的表现是双峰分布的：在大多数测试中，它几乎拿下了所有能拿到的增益，而在少数测试中几乎毫无斩获，正是这些少数测试把整体汇总数据拉低了。

接着我在上面拟合了一个[保序回归](https://en.wikipedia.org/wiki/Isotonic_regression)（isotonic regression），这样分数就有了实际单位，而不再只是一种相对感觉。这里适合用保序回归，是因为它只假设单调性（分数越高，点击率越高），这恰好是 Bradley-Terry 所保证的全部内容，也是它字面意义上唯一能保证的东西，任何参数化模型都会凭空捏造模型从未承诺过的结构。置信区间是通过对*测试组*（而不是单个变体）做 Bootstrap 抽样得出的，因为同一个测试内部的各个变体共享同一篇文章，彼此并不独立。

| 得分 | 相比基准 | 90% 置信区间 |
|---|---|---|
| −2.72 | **−19.1%** | [−0.252, −0.209] 百分点 |
| −1.06 | −8.2% | [−0.111, −0.086] 百分点 |
| −0.20 | −0.7% | [−0.023, −0.000] 百分点 |
| +0.56 | +3.7% | [+0.030, +0.056] 百分点 |
| +1.62 | +11.1% | [+0.115, +0.147] 百分点 |
| +2.82 | **+21.8%** | [+0.231, +0.274] 百分点 |

![校准曲线。相对于基准的点击率随着模型得分单调上升，90% 置信区间仅在接近中点的位置穿过零点。](/assets/img/blog/decision-models/calibration.png)

看看中间几行，置信区间在那里穿过了零点，这正是模型在准确地表达：“这两个标题差不多，掷硬币吧”。

## 再聊聊那个 0.544

我说过会回过头来聊这个。当我认真去查阅这份档案上还跑过哪些其他研究时，我之前一直依赖的那个对比基准变得站不住脚了，而我之前遗漏的某些东西反而变得相关得多。

| 来源 | 任务 | 指标 | 数值 | 纯随机概率 |
|---|---|---|---|---|
| LOLA，人类 (n=4,571) | k 选 1 最优 | 准确率 | ~随机 | 0.330 |
| LOLA，GPT-4 上下文学习 | k 选 1 最优 | 准确率 | 0.400 | 0.330 |
| LOLA，LoRA Llama-3-8B | k 选 1 最优 | 准确率 | 0.469 | 0.330 |
| LOLA，微调 GPT-4o | k 选 1 最优 | 准确率 | 0.488 | 0.330 |
| [arXiv:2506.00152](https://arxiv.org/abs/2506.00152)，Pythia-12B | 显著样本对，+ 导语 + 时间戳 | ROC AUC | 0.82 | 0.50 |
| [PLOS ONE 0281682](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0281682) | 匹配文章+配图+周次的样本对，K≤15 | 准确率 | 0.544 | ~0.50 |
| **VERA** | 所有同测试内样本对，仅标题 | 准确率 | **0.812** | 0.546 |

上面每一行跟我做的事情都不是同维度的直接对比，而这恰恰是问题的核心所在。

那篇 0.544 的论文在文章、配图*以及*测试周次上都对样本对进行了匹配，然后对任何超过 15 个样本对的实验进行了随机下采样。它是在 5,048 个样本对上训练的。而且它是一篇注册报告（registered report），其首要假设是“这玩意儿到底能不能被预测得比随机瞎猜好”——纯粹是个显著性检验。当时根本没人试图去把准确率刷到极限。用一个 4.35 亿参数的模型在多出一个数量级的数据上赢了它 27 个点，根本不配被当成我之前以为的那种值得吹嘘的战绩。

我真正遗漏的其实是那个 Pythia-12B 奖励模型，它是该数据集上遥遥领先的最强神经网络结果：ROC AUC 0.82。它只在点击率差异达到 5% 显著水平的样本对上训练（大约是最容易判断的前 28%），而且它在阅读标题的同时还会读文章导语和发布时间戳。所以它用的是更容易分类的标签集、包含了更多输入信息、考核的还是不同的指标，但即便如此它也没有超过 0.812。不过如果你只是把这两个数字并排扫一眼，它们看起来几乎一模一样，这种事情我宁愿自己先讲清楚，也不想等别人找上门来挑刺。

在这一切梳理完之后依然立得住的结论是：此前从未有人报道过微调 encoder 仅凭标题文本在未经筛选的同测试样本对上的成对准确率。这个结论虽然比“击败 SOTA”要窄得多，但至少是我能真正站得住脚的。

## 于是我自己跑了对比

上面提到的每个数字都是别人在别人的样本对上测出来的。所以我找了两个现有的系统在我的样本对上测了一遍。

每个样本对会询问两次：一次把胜者放在前面，一次放在后面，只有当两次顺序选择的都是同一个标题时才算有效。这个评测协议非常关键：无论内容是什么，模型选择选项 A 的概率都高于随机概率，因此单次顺序的评测实际上是在模型自己挑选出来的子集上给自己打分。

| 系统 | 参数量 | 匹配样本对 | 自洽度 |
|---|---|---|---|
| **VERA** | 435M | **0.823** | — |
| Gemini 3.1 Pro | 前沿模型 | 0.751 | 83.7% |
| Laya typed-decisions | 421M | 0.504 | 52.9% |

我之前一直挂在嘴边的一个论据这下也破灭了。我之前一直说人类在这个任务上的表现跟随机瞎猜差不多，以此暗示这个任务对模型来说也很难。事实并非如此，Gemini 能拿到 0.751。人类测试的结果只代表人类，对机器说明不了任何问题，我之前拿它来证明的事情根本就不成立。

不过实事求是的版本反而更好看：一个 4.35 亿参数的模型，以每次调用大约千分之一的成本，赢了前沿推理模型整整 7 个点。为了搞清楚这一点，花了我 5.60 美元的 Gemini 调用费。

Laya 是大家都会问起的一个开源决策模型，它在这里给出的回答自洽度跟抛硬币差不多。如果只把话说停在这儿未免有失公允，所以补充说明一下：它的模型卡片覆盖的领域是发票处理、安全事件、客户服务和 Agent 轨迹追踪。标题点击率在这四者之外。这是一个领域匹配度的问题，我相信让 VERA 去做发票处理肯定也会显得同样蠢笨。

这次对比还带出了另外一件事。Gemini 在那些点击率差距未达到 5% 显著水平的样本对（也就是我之前一直称为噪声的部分）上拿到了 0.641。它从未见过这些标签。这意味着一个完全接触不到结果数据的模型在这些样本上也能超过 0.500，也就是说这些样本对之间存在真实的差异，只是当初的实验样本量不够导致统计功效不足以证明它们显著而已。VERA 在同一分层上跑出 0.696 完全不需要用数据泄漏来解释，而在跑 Gemini 之前，我确实根本无法区分这两种情况。

## 好吧，接下来我要亲自打破这个幻想了

上面所有的数字，全部来自同一家媒体在 2013 到 2015 年期间爆火的社交网络标题，而我真正想做的东西是给邮件主题行打分。

一封发给 4,000 个主动订阅者的 B2B 新闻通讯，跟“这个孩子只用一句话就彻底粉碎了反对疫苗的全部论调”这种标题之间几乎没有半毛钱共同点。

所以我做了测试。如果眯起眼睛仔细看，Reddit 的数据形态其实跟这份档案差不多：SNAP 发布过 132,308 条发帖数据，其中相同的图片被换上不同的标题重新发了大约 8 次。同一张图，多个文本变体，一个测量出来的结果。共涉及 16,242 张图片。

由于这些数据并没有做过随机化实验，所以必须先排除三个干扰因素。首先，样本对只在同一张图片*且*同一个 subreddit 内部构建，以抵消社区层面的差异。其次，越晚发的帖子天生表现越差，所以我拟合了各 subreddit 内随发帖序号衰减的曲线，并对残差进行排序。最后，只有当残差差距足够大、能明确分出胜负时，样本对才会被保留。

最终得到 117,118 个样本对。VERA 的得分是 **0.522**。纯随机概率是 0.500。而一条“标题越长越容易赢”的简单规则就能拿到 0.507。

在这么大的样本量下，标准误差是 0.0015，因此 0.522 大约比随机概率高出 15 个标准误差，这确实是真实存在的信号，但微弱到了毫无实用价值的地步。准确率确实会随着残差差距的增大而上升，各四分位数之间呈现 0.508 → 0.531 的上升趋势，这表明这微小的效应确实是真实信号而非巧合伪影。它的分布范围从 r/WTF 上的 0.495 到 r/fffffffuuuuuuuuuuuu 上的 0.558 不等。

所以那个 0.812 的成果是专属于 Upworthy 的。VERA 学到的任何东西都只是某一家媒体在 2013 年的文风，它根本无法跨领域迁移。

我也给自己的反驳加个免责声明：Reddit 的点赞数不是点击率，而且发帖时间和发帖人的账号声誉也未受控制。这里的无效结果并不能干净利落地把“无法迁移”和“被混杂因素掩盖了”区分开来。但这是目前能做的成本最低的诚实验证，而且结果是负面的，我宁可去把测试跑出来，也不愿写一句“迁移能力尚未测试”然后任由读者抱有最好的幻想。

我真正想要的测试需要邮件数据。于是我去寻找包含真实发送结果数据的公开邮件数据集，结果发现：一份都没有。

| 数据源 | 规模 | 可用性 |
|---|---|---|
| Return Path 主题行研究 | 900 万主题行 | 专有数据，2015 年，从未公开 |
| Belkins B2B 语料库 | 550 万封邮件 | 仅提供聚合统计数据 |
| Yahoo (IEEE 7004277) | 10 万+ 主题行，数十亿次曝光 | 专有数据 |
| Oracle 的 NLORP 论文 | 300 条主题行 | 从 Google 抓取，未测量比率 |
| 各种 Kaggle “邮件营销”数据集 | 大小不一 | 模拟或合成数据 |

其中有一篇来自 Oracle 两位首席数据科学家的 arXiv 论文，他们的全部数据集居然是“通过 Google 搜索从多个互联网来源收集的 300 多个不同特惠邮件主题行”。顺便说一下，我不是在嘲讽他们，现实中公开发布的数据真的就只有这种水平。

各种汇总级别的规律到处都能搜到（比如 6 到 10 个单词效果最好、打开率最佳长度是 21 到 40 个字符、带数字能涨几个点），但没有一份是单次发送维度的真实结果数据，也根本无法用来训练任何模型。

## 这彻底重构了整件事情的意义

在被第二种意见打破幻想之前，我一直在用一个自我感觉良好的故事安慰自己。那个故事是：*模型架构是平价日用品，真正持久的资产是专有的结果标签*。前半句没错，但后半句纯属无稽之谈，因为我根本就*没有*专有标签。Upworthy 是公开的，任何拥有 GPU 的人花个周末、掏不到一杯咖啡的钱都能复现出我的 0.812，这也是为什么我直接把权重开源了的原因之一，一共才花了我 4 块钱，我总不能假装这是什么商业护城河吧。

我真正拥有的不过是一张证明自己做过的凭证。真正的资产应该是运行在线上真实流量中的持续测量反馈回路，而这目前根本还不存在。

我所需要的数据此时此刻正静静地躺在各大邮件服务商（ESP）的服务器里睡大觉，每一家带有 A/B 测试功能的 ESP 都有数百万次带有实测结果的主题行实验，但几乎没有一家在用这些数据训练模型。所以我不需要再多加一个分类头或者多跑一个 benchmark，我只需要认识一个手里掌握着这些日志数据的人。

## 这件事能够推广到的通用场景

这套方法平淡无奇到一句话就能讲完：如果存在测量出来的真实结果，就用它来训练，别再去问模型的看法了。

你们公司有史以来跑过的每一次 A/B 测试，现在都静静地躺在某个实验平台里，打好了标签，附带着结果，却什么也没干。Optimizely、Statsig、LaunchDarkly，不管你们用的是哪一家，里面都积攒了多年“我们试了这五个，结果这个赢了”的数据，却从来没人用它们训练过任何东西。

只要你手头有一组候选集，并且下游能产生一个量化指标，同样的逻辑就完全适用：

| 决策场景 | 你手中现成的真实标签 |
|---|---|
| 主题行、标题、推送文案 | 打开率、点击率 |
| 客服宏模板选择 | 是否在未升级工单的情况下解决 |
| 检索重排序（Reranking） | 用户最终采纳了哪条结果 |
| 错误提示文案 | 用户是自主解决了，还是提交了工单 |
| 商品标题 | 转化率 |
| Agent 工具调用选择 | 整个执行轨迹最终是否成功 |

如果你在做 Agent，最后一行会非常有意思。Jev 的三个原语是 choice、score 和 noul，这篇文章讨论的全部内容都落在 `score` 上，但在任何有人记录了决策之后发生了什么的地方，同样的套路也完全适用于 `choice`。只不过对于目前大多数 Agent 路由来说，还没有人在做这种记录而已。

不过对于这一切，还是要坦白指出一个局限：我手头其实只有这么一个数据点。用真实结果训练在*一个特定任务上*大幅击败了 zero-shot 判定，但这个优势在其他地方是否依然成立尚未经过验证，所以我敢押注的是这个发展方向，而不是具体的数字。

## VERA

**V**ariant **E**valuation from **R**eal **A**nalytics（基于真实分析的变体评估）。

**[`NovusEdge/vera-deberta-v3-large`](https://huggingface.co/NovusEdge/vera-deberta-v3-large)**，Apache 2.0 协议。

```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer

tok = AutoTokenizer.from_pretrained("NovusEdge/vera-deberta-v3-large")
model = AutoModelForSequenceClassification.from_pretrained(
    "NovusEdge/vera-deberta-v3-large")

# Score a set of candidates for ONE piece of content. Higher wins.
enc = tok(candidates, padding=True, truncation=True, max_length=64,
          return_tensors="pt")
scores = model(**enc).logits.squeeze(-1)
```

请务必将输出的分数作为一个整体来看待，绝不要把它当作孤立的单个数字。训练的目标是相对单次测试自身均值的偏差，因此单看一个分数毫无意义。你需要把为同一次发送所写的 3 到 6 个变体一起输入给它，让它来进行排序。仓库里也附带了一个校准器，可以将分数映射为预期的转化提升。

如果你觉得 4.35 亿参数太重了，上面也提供了一个适合 CPU 运行的版本：ModernBERT-base 在只有三分之一参数量的情况下能达到 0.761。

## 它做不到什么

迁移到邮件场景，或者说，我根本不知道它到底能不能迁移。

所以如果你运营着一份 newsletter，并且手头有历史发送记录以及测量过的打开率或点击率，我真心很想弄清楚这一点，欢迎联系我，数据依然完全归你所有。

## 总结

这个领域里的某一个开源权重模型，在它自己的 typed-decisions 基准测试上做 zero-shot 只能拿到 0.362，甚至低于 0.461 的多数类基线。

而从 0.637 到 0.812 的飞跃也不是靠什么精妙绝伦的建模技巧，其中三分之二的提升来自于选择了与评估指标相匹配的损失函数，剩下的提升则来自有人记录下了真实发生情况的 62,695 行数据。所以啊，如果你现在还在靠问大模型来给你的数据打标签，不妨先去找找真实数据（ground truth），它很可能早就安静地躺在某个地方了。
